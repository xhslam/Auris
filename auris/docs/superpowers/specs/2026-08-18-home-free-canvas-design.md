# Auris 首页「自由画布」实现规格

> **状态：设计规格，待实现。**  
> **决策：方案 C——自由画布 + 温柔吸附。**  
> **目标：将首页从固定三栏看板改造成用户可以亲手整理的个人学习空间，同时保留现有首页所有真实可用的数据与操作。**

## 1. 设计结论

本次首页改造的核心不是把卡片做得更“好看”，而是让首页成为用户拥有布局主导权的空间。`首页`默认仍提供一张经过设计的安静工作台；一旦用户按住卡片标题区拖动，卡片就可以在桌面任意位置停放、与其他卡片对齐或局部叠放。系统以轻微的吸附、辅助线和默认布局恢复功能维持秩序，但不替用户强行重排。

> **首页应该给人的第一感觉是：这不是软件替我排好的仪表盘，而是我可以随手整理的桌面。**

桌面端采用完整自由画布。窄屏和移动端不开放自由拖拽，改用稳定的单列阅读顺序，以避免小屏指针精度、遮挡和恢复布局的复杂度。该响应式取舍是本规格的默认产品假设；若后续需要移动端编辑布局，应作为独立需求重新设计，而不应直接移植桌面拖拽。

## 2. 现状审计与改造边界

现有首页已经有一套适合学习与 Markdown 工作流的真实能力，改造必须迁移这些能力，而不是用展示型 Mock 卡片替换它们。首页由 `DesktopHomeShell` 置于桌面应用框架中，实际页面为 `HomePage`，目前采用左侧资料与文件树、中间人生阶段、右侧计划与浏览器状态的固定三栏布局。

| 现有能力      | 当前入口 / 数据归属                                            | 自由画布中的处理                                  |
| --------- | ------------------------------------------------------ | ----------------------------------------- |
| 记录日历      | `CalendarHeatmap`，读取闪念记录日期                             | **保留**为“记录日历”卡片；仅改变位置和外壳，不改变统计语义。         |
| 本地工作区     | `NotesFileTree` + `useNotesWorkbench`                  | **保留**为“我的工作区”卡片；仍支持选文件夹、文件树、新建、改名、移动和删除。 |
| 快速笔记、快速闪念 | 首页按钮，跳转 `/notes` 与 `/flash`                            | **保留**在工作区卡片脚部，并在画布上提供更醒目的快速入口。           |
| 每日格言      | `DailyQuote`，写入 `HomeData.quote`                       | **保留**，但从大面积中心栏改为顶部情绪锚点 / 可放大的文字卡。        |
| 人生阶段      | `LifeRoad`，写入 `HomeData.lifeRecords` 与 `birthYear`     | **保留并强化**为默认居中的“人生之路”主舞台卡。                |
| 今日任务      | `PlanList`，支持完成、编辑、删除、记录到 Markdown、导出                  | **保留**为高频任务卡，保留所有操作与既有 `任务记录.md` 契约。      |
| 浏览器状态     | `BrowserStatusCenter`，来自桌面桥接                           | **保留**为低优先级“连接状态”卡；默认较小且允许折叠。             |
| 学习模块入口    | `/notes`、`/flash`、`/reading`、`/review`、`/video`、`/nia` | 作为快速入口和后续“继续学习”卡的数据来源，不在本期伪造新业务数据。        |

参考页面中最值得迁移的是**卡片拥有可抓取标题、放进中央工作区的自由感、低饱和纸面氛围、实时问候、状态微反馈与轻量悬浮动效**。其中的音乐、B 站嵌入和浏览器端直连 AI Key 不应原样复制：前两项偏离 Auris 的学习与笔记主线，后一项不符合正式应用的密钥安全边界。

## 3. 信息架构：从三栏到个人空间画布

### 3.1 固定框架与可移动内容

桌面应用框架、左侧主导航和窗口级控制继续由 `DesktopAppFrame` 负责；只有首页内容区域改造成 `HomeCanvas`。这样不会影响 `/notes`、`/reading`、`/review`、`/flash`、`/video`、`/nia` 等既有路由的导航模型。

画布顶部保留一条不参与拖拽的情绪头部：左侧显示日期与“早安 / 午安 / 下午好 / 晚安”，右侧显示本地时钟和一句非常轻的学习提示。除头部外，所有首页业务模块都以独立 `CanvasCard` 置入自由区域。头部不是传统 Hero Banner，不抢占主空间；它只负责让用户进入自己的桌面。

| 区域       | 是否移动 | 内容                   | 设计职责                |
| -------- | ---: | -------------------- | ------------------- |
| 应用外框与主导航 |    否 | 既有 `DesktopAppFrame` | 保持全局定位、路由和窗口体验稳定。   |
| 画布情绪头部   |    否 | 日期、问候、时钟、简短提示、布局菜单   | 建立进入感并提供布局恢复、卡片库入口。 |
| 自由画布     |    是 | 全部业务卡片               | 让用户依据今天的注意力和习惯安排信息。 |
| 画布底层背景   |    否 | 柔和纸面渐变、极弱网格 / 噪点     | 提供空间感，不增加信息负担。      |

### 3.2 默认布局：首次启动不是空白桌面

首次启动采用一个“安静学习桌”预设，保证用户不需要先学布局功能才看得懂首页。画布的中心仍由人生之路承担视觉重心；任务与工作区分别停在易访问的左、右两侧；日历、格言、专注和连接状态为较小的卫星卡。用户对任何卡片的移动都应立即变成自己的布局。

| 卡片 ID              | 默认名称   | 默认层级 | 默认尺寸倾向 | 默认位置与理由                                 |
| ------------------ | ------ | ---: | ------ | --------------------------------------- |
| `life-road`        | 人生之路   |  主舞台 | 大      | 中央偏下，占据最长的连续视觉区域，保留现有首页的情绪核心。           |
| `plan-list`        | 今日任务   |   高频 | 中      | 左上，打开首页后最容易看到和勾选。                       |
| `workspace`        | 我的工作区  |   高频 | 大      | 右上，支持文件树的纵向浏览与快速创建。                     |
| `daily-quote`      | 今日一句   |   情绪 | 小宽     | 顶部中间，可与头部形成安静的阅读停顿。                     |
| `calendar-heatmap` | 记录日历   |   反馈 | 小      | 左下，展示当月闪念与记录节奏。                         |
| `focus`            | 专注中    |   行动 | 小      | 靠近任务卡；第一期提供完整 25 / 5 分钟计时而非仅展示。         |
| `quick-capture`    | 快速记录   |   行动 | 小      | 靠近工作区；作为“新笔记 / 新闪念”的一键入口。               |
| `browser-status`   | 连接状态   |   系统 | 极小     | 右下，默认低存在感，异常时才提升提示级别。                   |
| `nia-entry`        | 问问 Nia |   可选 | 小      | 默认不抢占首屏，可从卡片库添加；点击仅导航 `/nia`，本期不嵌入完整聊天。 |

## 4. 组件规格与映射

### 4.1 核心卡片契约

每一张卡片都使用同一个外壳。外壳包含可拖动的标题手柄、标题、可选的副标题或实时状态、内容区域和一个只在悬停 / 键盘聚焦时显现的上下文菜单。业务卡片内部继续拥有自己的按钮、输入框、文件树和编辑行为；这些交互元素不能触发拖拽。

| 卡片     | 来源                        | 本期功能要求                                    | 参考页迁移的体验                      |
| ------ | ------------------------- | ----------------------------------------- | ----------------------------- |
| 今日任务   | 现有 `PlanList`             | 完成、编辑、删除、添加、记录到 `任务记录.md`、导出；保留完成数量。      | 圆形勾选、完成后轻微划线 / 淡化、进度随勾选即时过渡。  |
| 我的工作区  | 现有 `NotesFileTree` 与工作区逻辑 | 保留选文件夹、文件操作、文件打开、快速笔记、快速闪念。               | 透明纸面容器、底部快速操作胶囊按钮、悬停时仅轻提而不浮夸。 |
| 人生之路   | 现有 `LifeRoad`             | 保留年龄设置、节点选择与记录编辑。                         | 从固定中心栏转成可被用户围绕的“主舞台”，默认尺寸最大。  |
| 今日一句   | 现有 `DailyQuote`           | 保留可编辑与日期语义。                               | 用更强的衬线字和充裕留白，将它做成一句真的会被读到的话。  |
| 记录日历   | 现有 `CalendarHeatmap`      | 保留闪念统计与当天识别。                              | 卡片边框、低对比度的日历格、悬停才显现的信息反馈。     |
| 专注中    | 新增 `FocusTimerCard`       | 25 / 5 / 15 分钟模式、开始、暂停、重置、今日完成次数；数据本地持久化。 | 参考页的细线圆环、时间数字、模式切换与完成时温和反馈。   |
| 快速记录   | 由现有快速操作拆出                 | “新笔记”跳到 `/notes` 并创建页面；“新闪念”跳到 `/flash`。  | 像桌面上的小便签入口，而不是又一组大按钮。         |
| 连接状态   | 现有 `BrowserStatusCenter`  | 保留原状态与操作；支持折叠。                            | 正常时极安静，仅连接异常时提升边框和文本对比度。      |
| 问问 Nia | 既有 `/nia` 路由              | 只显示一句上下文行动提示与跳转，不复制聊天、世界书或 API 配置。        | 继承“陪伴感”，但不把复杂 AI 配置塞进首页。      |

### 4.2 不复制的参考功能

音乐和 B 站播放器不作为首页一级卡片。Auris 已有阅读、复习、视频和 AI 等学习模块；首页应帮助用户返回学习与笔记，而非成为泛娱乐容器。若产品以后已具备稳定的“正在学习 / 正在观看”数据，再以“继续学习”卡片接入 `/reading`、`/review` 或 `/video`，不能先做静态装饰。

角色聊天、世界书和直接填写第三方 API Key 也不迁入首页。角色体验可以在 Nia 路由中迭代；密钥与模型配置继续遵循应用既有的平台和设置层处理，不得写入首页的 `localStorage`。

## 5. 自由画布交互规范

### 5.1 拖拽与吸附

拖拽只能从卡片标题栏中标记为 `[data-home-canvas-drag-handle]` 的区域发起。内容区域中的按钮、链接、输入框、文本域、复选框、文件树和菜单必须被视为交互目标，不能被拖动行为劫持。实现应复用项目中现有的 Pointer Events + `setPointerCapture` 交互模式，而不是 HTML5 `draggable`。

拖动时，卡片以当前位置为基准随指针移动，卡片提升一个很小的阴影和层级；画布不自动把其他卡片推开。用户可以局部重叠卡片，确保“随便移动”的自由感不被网格算法夺走。拖动卡片靠近画布安全边、其他卡片的左 / 中 / 右边、上 / 中 / 下边，或 8 px 的隐形基线时，系统在 **12 px** 感应距离内显示细辅助线并吸附。松手后保留吸附后的坐标。

| 规则   | 规格                                               |
| ---- | ------------------------------------------------ |
| 可用区域 | 画布内边距 16 px；卡片不能完全拖出可视画布。                        |
| 吸附候选 | 画布左右 / 上下安全边、画布中心线、其他可见卡片的三条水平边与三条垂直边、8 px 基线。   |
| 感应距离 | 12 px；多个候选并存时，优先画布安全边，再优先卡片边缘，再优先 8 px 基线。       |
| 放置   | 不执行强制避碰和强制自动排列；允许重叠。若重叠超过 60%，只给出轻微的“叠放”轮廓提示。    |
| 层级   | 拖动开始时卡片临时置顶；拖动结束后将该卡片带到当前用户布局的最上层，并持久化 `zIndex`。 |
| 拖动阈值 | 指针移动小于 4 px 仍视为点击，不能吞掉标题菜单或焦点行为。                 |
| 锁定   | 锁定卡片不会响应拖拽或缩放，但内部内容仍可操作。                         |

### 5.2 缩放、折叠与布局控制

每张卡片右下角在悬停或聚焦时显示缩放手柄。缩放遵守各卡片最小尺寸与内容可读性约束；文件树、人生之路和任务卡需要更高的最小高度。用户可从卡片菜单执行“锁定位置”“折叠”“置于顶层”“恢复默认尺寸”“从桌面移除”。被移除的卡片只从布局中隐藏，不删除业务数据，可在“添加卡片”面板恢复。

顶部布局菜单提供“添加卡片”“恢复安静学习桌”“保存为我的默认布局”和“撤销上一次布局操作”。恢复默认布局必须有确认，并在执行后提供 10 秒撤销提示。布局操作与内容操作分离：恢复布局不能清空任务、笔记、人生记录、闪念或专注统计。

### 5.3 键盘与无障碍

拖拽手柄必须是可聚焦按钮，并提供清晰的 `aria-label`，例如“移动 今日任务”。键盘用户在手柄聚焦后，可用 `Alt + Shift + Arrow` 每次移动 8 px，用 `Alt + Shift + Ctrl + Arrow` 每次移动 40 px；`Enter` 打开卡片菜单，`Escape` 取消当前拖拽或缩放。所有辅助线仅作为视觉反馈，不能成为使用功能的唯一方式。

`prefers-reduced-motion: reduce` 下不得出现入场错落、浮动和回弹；拖动只更新位置，放置不播放弹性动画。颜色不是状态的唯一载体：锁定、折叠、连接异常和任务完成均需搭配图标、文本或 `aria` 描述。

## 6. 视觉与动效规范

### 6.1 视觉语言

目标不是复制参考页的纯灰色，而是把它的“雾面纸张 + 大留白 + 编辑感排版”翻译进 Auris 已有主题系统。现有 `home-v3` 已在白纸、纸张、薄荷、棕褐、夜间和 Solarized 等主题下定义色彩变量；新画布必须继续读取应用主题变量，不能锁死为单一灰色或在线字体。

画布使用现有主题背景上的两个弱径向光晕和不显眼的纸面颗粒。卡片使用低透明度面板、1 px 柔和边线、12–16 px 圆角和克制阴影；默认状态不应大面积使用 `backdrop-filter`，以保护桌面端的渲染稳定性。排版延续现有字体栈，并将衬线字只用于问候、时钟、格言与人生之路等情绪文字；工具型文字仍以清晰易读为优先。

| 元素    | 默认视觉                     | 动效与时长                             |
| ----- | ------------------------ | --------------------------------- |
| 画布背景  | 主题色纸面 + 极弱中心光晕           | 仅首屏淡入，180 ms。                     |
| 卡片静止态 | 半透明面板、细边线、微弱阴影           | 无持续漂浮，避免分散学习注意力。                  |
| 卡片悬停  | 向上 2 px，边框对比略增           | `transform` / 阴影，160 ms，ease-out。 |
| 拖拽中   | `scale(1.012)`、阴影加深、光标抓取 | 不使用 CSS transition，跟手优先。          |
| 吸附辅助线 | 1 px 主题强调色，低不透明度         | 90 ms 淡入淡出。                       |
| 松手归位  | 如发生吸附，位置短促落位             | 180–220 ms，非弹簧或极轻弹性。              |
| 任务完成  | 勾选、文本划线、进度过渡             | 180–260 ms；不抖动、不撒花。               |
| 专注完成  | 圆环完整、简短文本提示、可选系统通知       | 260 ms；尊重系统通知权限。                  |
| 首屏入场  | 头部先出现，卡片按阅读顺序轻淡入         | 仅首次加载，最多 6 组、间隔 35 ms。            |

### 6.2 卡片密度规则

每张卡片只保留一个主动作，其他动作移入悬停菜单或二级按钮。卡片标题使用 14–16 px，副标题使用 11–12 px；工具行高度不低于 32 px；内容区不应因为自由缩放而显示不可用的横向滚动条。任务与工作区等可滚动卡片的滚动条仅在悬停或滚动中提高可见度。

## 7. 布局数据与持久化

业务内容继续沿用现有 `auris:home:v1` 的 `HomeData` 以及笔记 vault、闪念存储和桌面桥接数据。**布局必须使用独立存储键**，以避免一次布局升级影响已有计划、格言和人生记录的读取与迁移。

```ts
export const HOME_CANVAS_LAYOUT_STORAGE_KEY = "auris:home-canvas-layout:v1";

type CanvasCardId =
  | "plan-list"
  | "workspace"
  | "life-road"
  | "daily-quote"
  | "calendar-heatmap"
  | "focus"
  | "quick-capture"
  | "browser-status"
  | "nia-entry";

type CanvasCardLayout = {
  id: CanvasCardId;
  visible: boolean;
  collapsed: boolean;
  locked: boolean;
  x: number; // 1600 × 960 基准画布坐标
  y: number;
  width: number;
  height: number;
  zIndex: number;
};

type HomeCanvasLayout = {
  schemaVersion: 1;
  preset: "quiet-study-desk" | "custom";
  updatedAt: string;
  desktop: Record<CanvasCardId, CanvasCardLayout>;
};
```

布局坐标以 **1600 × 960 逻辑画布** 保存，并在渲染时根据实际可用宽高缩放、夹紧到安全边界。持久化只在拖拽结束、缩放结束、折叠 / 锁定 / 显隐 / 层级变更和明确恢复布局时写入；拖动过程使用 `requestAnimationFrame` 更新临时显示状态，不应在每一个 pointer move 中写入 `localStorage`。窗口大小变化不会破坏布局：卡片按缩放后的逻辑坐标重新计算，若最小尺寸与安全边界冲突，先保留卡片可见性，再做夹紧。

首次读取不到布局、布局 JSON 不合法、版本不支持或缺少新卡片时，必须返回默认预设并补齐缺失卡片；不得抛错或阻止首页渲染。将来如支持云同步，应同步 `HomeCanvasLayout` 这一独立对象，而不是把它与 Markdown 内容混杂。

## 8. 推荐组件拆分与实现路径

本规格不要求一次性重写所有业务逻辑。优先把现有 `HomePage` 拆成“内容控制器”和“可复用卡片外壳”，让原有业务组件保持可测试的纯内容职责。

项目已有 `use-floating-word-card-drag.ts`，它已经采用 Pointer Events、手柄限定、交互目标排除与 `setPointerCapture`。自由画布应抽取或泛化其中的通用机制，而非新引入 HTML5 原生拖放。当前依赖中没有成熟的网格拖拽库；本期不强制引入新库。若实现阶段评估发现缩放、多卡片辅助线和键盘操作已超过可维护范围，可单独提出采用成熟库的技术决策，但不得在未评估前把布局语义交给自动排版网格。

## 9. 响应式、性能与安全边界

| 条件                       | 交互与布局规则                                                                    |
| ------------------------ | -------------------------------------------------------------------------- |
| 宽度 ≥ 1024 px 且精细指针可用     | 完整自由画布；可拖动、缩放、折叠、锁定与吸附。                                                    |
| 宽度 < 1024 px 或触摸为主       | 禁用拖拽与缩放；按“今日任务 → 快速记录 → 我的工作区 → 专注中 → 人生之路 → 记录日历 → 今日一句 → 系统状态”的固定单列顺序展示。 |
| 低高度窗口                    | 画布整体可纵向滚动；头部保持紧凑，不使用固定定位遮挡卡片。                                              |
| `prefers-reduced-motion` | 取消入场错落、悬浮与放置回弹；保留即时状态变化。                                                   |
| 主题切换                     | 通过现有桌面主题变量实时更新；不重置用户布局。                                                    |

拖动过程中只更新当前卡片，不应让文件树、人生之路和日历重复渲染。应使用 `requestAnimationFrame` 合并指针移动；业务内容使用 `React.memo` 或等价边界避免因为位置状态而刷新。画布内默认卡片总数控制在 9 张以内；后续卡片库可添加更多，但应提示用户卡片密度而不自动塞进首屏。

本期不在首页读取或保存第三方 API Key，不改变笔记 vault 的文件操作权限，不把浏览器状态的敏感信息写入布局存储。布局数据只包含卡片 ID、位置、尺寸、可见性与显示偏好。

## 10. 验收标准

### 10.1 产品验收

| 编号    | 可观察标准                                                 |
| ----- | ----------------------------------------------------- |
| AC-01 | 初次打开桌面端首页可见完整默认工作台，并同时包含现有任务、工作区、人生之路、格言、日历和浏览器状态能力。  |
| AC-02 | 用户只能通过卡片标题手柄拖动；点击任务复选框、编辑任务、操作文件树、输入格言和使用菜单均不会意外启动拖拽。 |
| AC-03 | 卡片靠近画布边、中心线或另一张卡片的边时，在 12 px 内显示辅助线并在放开后吸附。           |
| AC-04 | 两张卡片可局部重叠；系统不强制挤开用户已放好的卡片。                            |
| AC-05 | 拖拽、缩放、折叠、锁定、显隐与层级变化后刷新应用，布局保持不变。                      |
| AC-06 | “恢复安静学习桌”只恢复布局，不清空任务、格言、人生阶段、闪念、工作区或专注统计；执行后可撤销一次。    |
| AC-07 | 缩小到移动断点时，全部保留卡片内容和关键操作，且不出现无法操作的重叠与横向滚动。              |
| AC-08 | 每个拖拽手柄可键盘聚焦；键盘能移动卡片，屏幕阅读器能感知卡片名称与锁定状态。                |
| AC-09 | 现有任务记录与导出、文件树操作、快速笔记、快速闪念、人生记录和浏览器状态测试继续通过。           |
| AC-10 | 在减少动态效果偏好下，首页没有入场错落、弹跳或持续悬浮。                          |

### 10.2 测试要求

实现必须新增布局纯函数的单元测试，覆盖默认预设、非法存储恢复、卡片迁移补齐、坐标夹紧、边缘 / 中线 / 卡片边吸附优先级、窗口尺寸变化、层级更新与移动端阅读顺序。组件测试应覆盖拖拽手柄启动、交互内容不启动拖拽、锁定禁用、恢复布局以及任务 / 工作区既有动作保持可用。端到端或人工验收至少在 1440 × 900、1280 × 720、1024 × 768 与手机窄屏四种尺寸下执行。

## 12. 非目标与待确认事项

本期不实现任意卡片内容的在线协同，不做多设备云同步，不做移动端自由布局编辑，不复制音乐 / B 站嵌入，也不在首页嵌入完整 Nia 对话或第三方 API 配置。首页自由度的边界是“整理自己的学习桌面”，而不是提供无限画布、白板或通用窗口管理器。

如果后续要支持多个命名预设，例如“复习模式”“写作模式”“极简模式”，可以在 `HomeCanvasLayout` 之上增加 `layoutsByName`，但第一版只保存一个用户布局并提供一个系统默认预设。这样能先把拖拽体验做对，避免布局管理本身盖过学习行为。

## 14. 工程轨迹

本任务被定义为一次首页体验规格工作，而非直接改动产品代码。审阅先确认了当前首页由工作区、记录日历、每日格言、人生之路、今日任务和浏览器状态组成，并确认这些组件已连接本地 vault、首页存储或桌面桥接；因此采用“外壳重构、业务能力迁移”的路径，而不是用新的展示卡片替代已有功能。

规格选择“自由画布 + 温柔吸附”，原因是用户明确将可任意整理的空间感视为首页最重要的体验。实现建议复用项目已有的 Pointer Events 拖拽模式，并把布局数据从既有 `HomeData` 中独立出来，避免影响任务、格言和人生记录的兼容性。文档写入 `docs/superpowers/specs/2026-08-18-home-free-canvas-design.md`；已执行章节与关键契约校验，确认文件包含现有组件映射、布局存储键、吸附阈值、减少动态效果要求、验收标准和分阶段实施顺序。当前未修改任何产品源码、依赖或运行配置。
