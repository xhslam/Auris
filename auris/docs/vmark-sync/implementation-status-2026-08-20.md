# Auris 差异补齐实施状态

> 日期：2026-08-20（GMT+8）
> 范围：基于 `feature-gap-report-2026-08-20.md` 的源码复核后，对**确认存在且可在当前桌面架构内闭环**的 PDF 交付质量与学习产物依赖复核能力进行实现。

## 结论

本轮完成了两项可交付能力。第一项是将已有的桌面 PDF 导出提升为具有 **A4 版式、页码页脚、可访问标签与文档大纲请求**的受限输出路径。第二项是为学习笔记建立了“**来源指纹 → 来源变化自动标记 → 工作台人工确认 → 基线刷新**”的可审计闭环。

源码复核同时纠正了上一版差异报告的两项判断：Auris 在本轮开始前已经有基于 Electron `printToPDF` 的 PDF 导出路径；受管浏览器也已经具备脱敏、审批、租约、恢复和运行状态能力。因此没有重做这两条已存在的基础设施，也没有触碰用户当前未提交的浏览器界面改动。

| 对齐项 | 用户问题 | 已实施结果 | 技术边界 |
|---|---|---|---|
| 桌面 PDF 交付 | 导出笔记不应只是静态打印结果，而应适合作为可读、可导航、可存档的交付物。 | 默认 A4、背景打印、CSS 页面规格、页码页脚，并向 Chromium 请求 Tagged PDF 与 Document Outline。 | 渲染进程仅可传递纸张、横竖向和两项可访问性开关；页脚模板、范围等主进程参数不可由渲染端注入。 |
| PDF 阅读语义 | 长笔记中的标题、表格、引用、代码与图片不应在页面边界被随意拆开。 | HTML 导出加入页面规格、语义 `<main>`、标题断页控制与块级避免跨页规则。 | 大纲提取依赖 Chromium/Electron 的 PDF 引擎；不能保证所有第三方阅读器都以同一方式呈现。 |
| 学习产物血缘 | 当来源材料变化后，旧学习笔记容易在无提示下继续被复用。 | 创建学习笔记时记录材料和来源笔记的标准化指纹，写入 `aurisDependencySnapshot` frontmatter 和可读审计区块。 | 当前自动同步覆盖 Auris 的来源材料创建、摘录和词汇追加路径；用户直接在其他入口手工改写来源文件后，需在后续统一保存钩子中继续接入。 |
| 待复核处置 | “已过期”需要一个能完成、可追踪的处理动作，而非仅有告警。 | 来源变化将相关学习笔记标为 `needs-review`；工作台底部显示“待复核”，确认后重建当前来源指纹并写入 `reviewed` 决策与时间。 | 当前界面提供“确认已复核”；“豁免并附理由”已有领域模型和校验，尚未增加独立界面动作。 |

## 实现清单

PDF 路径新增了 `electron/pdf-export-options.cjs`，将默认能力和严格输入归一化从主进程提取为可测试模块。`electron/main.cjs` 与 `electron/preload.cjs` 仅扩展既有 `shadowing:downloads:export-pdf` IPC 的第三个、可选参数；`DesktopBridge` 与文件导出服务保持网页回退兼容。用户已明确授权这一最小范围的主进程和预加载改动。

学习血缘路径新增 `learning-dependency-review.ts`、`learning-dependency-sync.ts` 和 `learning-dependency-note-update.ts`。它们分别负责确定性指纹与状态机、来源变化时批量同步及工作台原始 Markdown 写回。学习笔记模板在 frontmatter 与正文中同时保存快照；来源材料保存、摘录追加和词汇追加后触发同步；`NotesWorkbench` 提供人工确认入口。

## 剩余差异与建议

本轮不把“本地知识库阅读/检索”列为已完成：Auris 已有 vault、笔记检索和受管浏览器，但尚未形成 VMark 风格的独立知识库统一阅读面。如需继续对齐，应单独定义索引范围、文件授权模型、PDF/EPUB 解析和离线搜索性能目标，而不应把它混入本轮 PDF 或学习笔记变更中。

浏览器工作流录制、人工接管和执行观测没有在本轮改动。理由是现有 Auris 已具备更严格的分区隔离、操作审批、能力租约与恢复状态；未来若需提升，应集中在“工作流编辑器的可视化步骤记录和回放诊断”这一产品层，而不是降低既有安全约束。
