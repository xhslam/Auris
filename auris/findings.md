# Findings

## Environment

- 主工程目录是 `english-shadowing-web`
- 技术栈：Next.js 16、React 19、Electron、Capacitor、Supabase、Vitest、Playwright
- 当前项目已有较好的本地优先架构、组件测试和 E2E 冒烟测试

## Baseline Product Read

- 首页结构清晰，但偏“空”和“稳”，缺少让陌生人眼前一亮的产品叙事与成长氛围
- 训练页已有不错的深色工作台基底，但输入面板偏工具化，缺少目标感、节奏感和即时反馈
- 播放区控件功能在，但“练习状态可感知性”和“操作仪式感”还可以更强
- 已有测试面覆盖不错，适合持续做不破坏底盘的精修升级

## Inspiration Notes

- GitHub 检索到直接相关开源项目很少，`Dthurow/SpeechShadowing` 说明 shadowing 工具赛道本身稀缺
- 更有价值的方向不是机械模仿同类，而是把“语言学习 + 阅读器 + 本地工作台 + 音频训练”融合成更完整的体验
- 现有项目内自己的设计资产和结构文档，比外部零散参考更值得延续
- 本轮补充参考了 `Joplin`、`BoostNote-App`、`TidGi-Desktop` 这类桌面工作台产品，重点借鉴它们的“恢复入口更近、摘要信息更先出现、资源列表不只是一串名字”

- 当前 MCP 盘点结果：
  - `vmark`：文档与窗口资源
  - `github`：仓库内容模板与搜索能力

## Sidebar Debug Findings

- “最近 / 模板”按钮并不是点击失效，点击后 `aria-expanded` 和面板 DOM 都正常变化
- 真正问题在于桌面布局专用 CSS 把 `.workspace-sidebar__panel` 绝对定位到了可视工作台之外
- 修复关键点：
  - 让 `.workspace-shell` 成为桌面弹层的稳定定位上下文
  - 把桌面侧栏面板的 `left` 改为相对左轨宽度的固定值，而不是 `100%`
  - 同步把桌面遮罩改为相对工作区定位，避免覆盖和点击层级再次错位

## Sidebar Upgrade Findings

- 对桌面工作台来说，资源侧栏最重要的不是“列表渲染出来”，而是：
  - 用户能一眼看到自己可以恢复什么
  - 用户能直接进行主操作，而不是先阅读列表再决定
  - 模板不应该只有标题，至少要提供难度、描述和文本量信号
- 给最近记录增加“继续上次”卡片后，恢复路径明显更短，也更符合桌面产品的工作流直觉
- 给模板增加描述与词数后，模板更像训练资产，而不是冷冰冰的内部数据

## Final Findings After Iteration

- 首页完成了从“入口页”到“学习中枢”的升级：
  - hero 文案更强
  - 增加了脉冲卡、节奏卡、恢复资产信号
  - 顶部 workspace meta 更完整
- 工作区完成了从“表单 + 播放器”到“训练启动台 + 练习概览”的升级：
  - 增加训练概览条
  - SourcePanel 增加标题、收益、模式解释与摘要卡
  - PlaybackDock 增加状态 pill、进度条、教练式提示
- 测试层同步升级：
  - 新增首页 hero 与训练输入标题断言
  - 新增播放状态反馈断言
  - E2E 覆盖新文案与新输入控件

## Reusable Lessons

- 真正能显著提升高级感的，不是堆更多功能，而是把已有能力重组成更强的信息层级
- “惊艳感”在学习产品里更适合通过节奏、恢复感、成长证据来建立，而不是营销式夸张视觉
- 在已有完整测试面上做迭代，最优策略是：
  - 先抓基线截图
  - 再做聚焦组件改造
  - 立刻补断言
  - 最后回归全量验证
- 修桌面 bug 时，必须同时验证：
  - DOM 是否真的打开
  - 面板是否处在可视区域
  - 在真实 Electron / desktop shell 样式下是否依旧可点击

## Desktop Platform Findings

- 这轮用户给出的参考图不是单页灵感，而是一整套桌面产品语言：
  - 左侧有稳定导航
  - 中间是按任务类型分层的工作面
  - 每个页面都像一个独立应用，但又属于同一套系统
- 真正需要“模仿”的不是单个卡片，而是统一的桌面秩序：
  - 首页像学习中枢
  - 聊天像带历史列表的工作台
  - 社区像带筛选和主题列表的内容中心
  - 音频 / 视频 / 文档像资源库
  - 设置像桌面模态中心

## GitHub Inspiration Findings

- 本轮再次确认 GitHub 直接搜“shadowing desktop / learning desktop”召回质量很不稳定，很多结果噪声极大，不能机械照搬。
- 相对有效的灵感仍来自已确认的桌面工作台仓库：
  - `Joplin`：分栏、摘要优先、内容与导航的桌面秩序
  - `BoostNote-App`：知识资产卡片化、工作区切换感
  - `TidGi-Desktop`：桌面容器与工作台视角
- 推论：你的产品更适合沿着“桌面学习工作台”而不是“单一 shadowing 小工具”继续做大。

## V21-V30 Findings

- 新增独立桌面页后，项目从“训练工具 + 附属页面”更像“完整的语言学习桌面端”：
  - 导航分组后，信息架构更像产品而不是开发菜单
  - 首页的课程 / 音频 / 视频三段式布局更接近用户对平台首页的直觉
  - 聊天页加入历史、快速操作和消息动作后，更接近真实训练助手
  - 资源页加入概览摘要后，不再只是把卡片堆满屏幕
- 本轮最重要的技术发现之一是：
  - 当首页 hero 按钮与侧栏导航重名时，Playwright 的可访问名称会产生歧义
  - 解决方式不是删入口，而是明确区分动作语义，例如“聊天”与“继续对话”
- 这轮补出来的新测试价值很高，因为它们锁定的是“桌面页面是否成立”，而不只是某个小组件是否渲染。

## New Reusable Lessons

- 当用户给的是一组页面截图时，优先抽象出“系统级骨架”而不是局部视觉碎片。
- 做桌面端仿制升级时，最容易被忽略的是：
  - 导航分组逻辑
  - 标题 / 按钮的可访问名称冲突
  - 内容页之间是否共享同一套节奏和视觉密度
- 先让主页、聊天页、资源页、设置页都成立，再继续做细节，会比单点极致美化更有产品飞跃感。

## V31-V40 Findings

- 课程页如果继续沿用通用资源页壳层，虽然能看，但缺少“学习路径”感；因此这轮把它升级成了独立 `CoursesShell`。
- 课程页最关键的新信息层不是课程数量，而是：
  - 本周主题
  - 可续练状态
  - 课程与训练 / 纠音 / 笔记之间的联动
- 社区页从“像一个论坛页面”进一步升级到“像一个会被继续使用的论坛首页”，关键在于：
  - 发帖前搜索提示
  - 热榜摘要
  - 发布动作入口
- 聊天页继续深化后，一个很明确的结论是：
  - 对话页不能只负责交流
  - 它应该同时承担“资产生成面板”的角色，把聊天内容沉淀成训练、词条和笔记
- 这轮的结构升级仍然证明了同一个原则：
  - 让页面更惊艳，不一定要加复杂交互
  - 把“下一步动作”和“已有资产”摆在一起，产品完成度就会跃升

## Additional Reusable Lessons

- 通用页面壳层适合快速铺图，但当某个页面承担更明确的产品职责时，应该尽早抽成独立 shell。
- UI 迭代的高价值测试，不只是断言标题出现，而是断言“产品层语义”出现，例如：
  - `会话资产`
  - `本周训练节奏`
  - `发帖前先搜一搜`
- 当外部对标图很多时，第二轮迭代最值得做的不是继续抄布局，而是开始补这些页面真正该有的工作流。
- 如果 `next build` 只在 `.next/dev/types` 上报错，而应用编译本身通过，需要警惕是 Next 生成的路由类型文件污染或缺项，不一定是业务源码有问题。
