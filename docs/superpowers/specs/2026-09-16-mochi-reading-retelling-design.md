# 基于 Mochi 的极简英文阅读与复述工具

日期：2026-09-16
状态：设计规划草案；已完成关键需求澄清，尚未进入开发。

## 1. 目标与已确认需求

做一个独立桌面工具，让用户读英文文章、划出关键词，然后只看关键词用英文复述。AI 听完后给出建议，用户继续练习，直到能完整表达本次材料的核心意思。

用户已确认：

- 独立应用，可基于 Mochi 开发。
- 本地导入 Markdown、TXT、PDF；也支持粘贴网页链接并提取正文。
- 支持整篇复述和选取部分内容复述。
- 必须由用户点击“说完了”触发反馈，思考和停顿不能触发 AI 抢话。
- 不固定反馈模板、语言、条数或纠错比例；由模型根据实际表现决定。
- “gpt-live”指 Mochi 式实时语音，优先沿用通过 Codex 登录的连接方式，不要求接入官方独立的 GPT-Live 接口。
- 简洁是首要产品约束。

以下为规划默认值，可以在审阅时调整：首版面向 macOS；反馈通过语音播放并保留文字；文章、划线和最近一次练习反馈保存在本地；不默认保存原始录音。

## 3. 用户流程

### 导入与阅读

首页只提供“打开文件”“粘贴链接”和简短的最近文章列表。导入后进入同一个阅读窗口，显示标题、来源和正文。

- Markdown/TXT：保留标题、段落和列表的阅读顺序。
- PDF：先支持带文本层的 PDF，提取为适合划线的正文，不要求复刻纸张排版。
- 网页：提取可直接访问的文章正文，尽量排除导航、广告和评论，保留原标题及来源链接。
- 导入后先显示正文供用户检查。内容明显为空、乱码或阅读顺序异常时，不能宣称导入成功。
- 选中的单词或短语可直接划线、取消；重复出现的同一个词按具体位置保存，不全篇同步标记。

扫描 PDF、复杂表格/多栏版面，以及需要登录、付费或复杂脚本渲染的网页，不作为首版保证。失败时说明原因，并提供换用文本文件或粘贴正文的补救入口；OCR 和登录浏览器另行扩展。

### 选择范围

默认练习整篇文章。用户也可选择连续若干段作为本次范围，避免引入复杂章节管理。界面明确显示当前练习的是整篇还是部分段落。

划线与范围互相独立：划线决定提示内容，范围决定 AI 要核对的原文。不能因为某段没划关键词，就把该段从评价范围中删掉。

### 关键词复述

进入复述模式后，仅按原文顺序和段落分组显示范围内的关键词/短语。正文、译文、自动摘要和 AI 提取的答案不显示。没有关键词的段落只保留中性的段落标记，不自动补答案。

没有任何划线时，提示先划词；用户也可以明确选择无提示练习。点击“开始复述”后开启麦克风，窗口清楚显示正在收音。

AI 接收完整的本次原文范围、用户划线和本轮语音。用户可以停顿、自我纠正、改变表达顺序。只有点击“说完了”才进入反馈阶段。

### 反馈与再练

模型自行决定如何反馈。提示只约束任务目的和证据边界：帮助用户完整、准确地表达文章核心意思，允许自然转述；需要听清且有原文依据才能指出错误或宣布完成。不设关键词命中率、固定分数或机械纠错清单。

反馈以语音播放并显示文字，可停止播放。反馈阶段停止向服务发送麦克风音频，避免把扬声器回声当作新一轮复述。

用户可以点击“再试一次”“返回原文”或“结束练习”。再次复述时恢复关键词界面，收起前轮反馈，避免把答案长期展示在提示区。

上一轮反馈可用于判断进步，但“这一轮已完整复述”的判断必须基于这一轮实际表达；不能将多轮各说过一部分拼成完整掌握。选段练习的完成结论仅适用于选段；需要整篇结论时进行一次完整范围的复述。用户可以随时结束，不设置强制通关。

## 4. 最小实现结构

仅保留四个主要边界：

1. **导入与本地文章**：文件解析、网页正文提取、来源信息及正文快照。
2. **阅读与练习范围**：段落、划线位置、整篇/选段和关键词显示。
3. **语音会话**：Codex 凭据、WebRTC、麦克风、播放、手动触发和连接故障。
4. **练习状态**：当前文章版本、当前范围、本轮音频片段关联、反馈和重试。

状态流为：阅读 → 关键词就绪 → 正在复述 → 提交本轮 → 等待反馈 → 展示/播放反馈 → 再试或结束。连接失败和导入失败都有可见的错误状态。

凭据仅留在主进程，不传给页面、写入练习记录或日志。已导入文章的阅读和划线可离线使用，网页导入需要访问目标网站；开始 AI 练习时会将本次范围的原文与语音发送给服务。默认不上传整份 PDF 或范围之外的文章内容。导入文章作为学习材料处理，其中的文字不能改变应用指令或获得工具权限。

不向语音模型提供文件修改、终端、浏览器操作或个人记忆工具。学习任务只需要文章上下文和语音。

### 回合控制

Realtime 官方文档支持保留语音活动检测，同时设置 `create_response: false` 和 `interrupt_response: false`，再由客户端发送 `response.create`。具体实现需确认配置已被服务接受后才开始收音；移除 Mochi 的主动问候和静默触发逻辑。

一次复述可能由多个语音片段组成，停顿形成的片段不能被当作一轮结束。点击“说完了”后，需完成尾部音频提交并确认本轮输入已进入会话，再请求反馈；不能只评价最后一个片段。空输入、重复点击、晚到的转写和断线都不能产生重复或虚假的完成结论。

长文章不能静默截断后声称评估了全文。若所选材料超过已验证的会话容量，应明确要求缩小本次范围；具体长度和连续语音限制由连通性实验确定。

### 本地保存与恢复

保存正文快照、来源、段落 ID、划线位置、当前范围和最近一次练习结果。划线绑定具体正文版本，原文件或网页变化不会悄悄改变练习依据。首版不自动同步外部来源，不改写用户源文件。

返回阅读、切换文章、退出练习或关闭窗口时释放麦克风和连接。切换文章或练习范围时开始独立的练习上下文，不把旧范围的语音和完成结论算入新练习。断线后保留文章和划线，说明当前轮是否完整；不能把不完整轮次判为通过。重新连接时重新提供本次范围；跨会话延续本轮音频未经验证时，让用户重试本轮。

## 5. 实施顺序与验收

### 第一步：验证最高风险的语音链路

从固定的 Mochi 归档提交准备隔离工作副本，先验证 Codex 登录 → 会话兑换 → SDP → 实际音频输入和反馈。仅拿到临时凭据不算连通成功。

验收重点：能听见完整语音反馈；可传入短篇原文；连续停顿不抢话；点击后只反馈一次；登录过期、连接失败和麦克风拒绝有可理解的错误。当前账号能否连接、模型是否可用、额度如何适用，均以当时服务结果为准，不预先承诺免费或无限量；若原接入方式不可用，报告具体障碍，不暗中切换付费 API。

### 第二步：完成导入和关键词练习

完成统一正文、划线/取消、整篇/连续选段、本地保存及关键词切换。覆盖 Markdown、TXT、文本 PDF、普通公开网页各一份样本，以及重复词、跨文本节点短语、空文件和提取失败。

### 第三步：接通完整复述循环

将文章范围交给 AI，完成开始、说完、反馈、重试和结束。验证反馈范围正确、多轮不串线、前轮建议可收起、离开后停止收音，以及断线重连不会假称保留了全部语音。

### 第四步：用真实材料验收并打包

至少验证：一篇短文整篇复述；长文选段；关键词相同但意思讲错；正确使用同义表达；多次长停顿；没有有效语音；结尾立即点击；重复点击；中途断线；两轮各讲一半；有缺失的 PDF 提取结果。

最终交付独立 macOS 应用。名称、图标和安装路径在开发交付阶段确定，不影响当前方案。先完成学习流程，不加入成绩面板、打卡、间隔复习、云同步或完整桌宠角色系统。
