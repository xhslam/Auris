# Auris 横竖屏视频全屏体验设计

**日期：** 2026-07-17

**状态：** 已经用户确认，等待实现计划

**范围：** `auris/` 桌面端视频详情页
**视觉决策：** 竖屏全屏采用严格 50/50 布局；侧边栏在全屏时完全隐藏

## 1. 背景

当前视频详情页在非全屏状态采用左侧播放器与跟读区、右侧双语剧本的双栏骨架。横屏视频在这个骨架中表现正常，但竖屏视频被放进固定 `16:9` 播放器后，两侧形成大面积黑边，实际画面过窄；点击全屏还会出现“无法进入全屏模式”。

现有实现对 `.video-study__player-frame` 调用 `requestFullscreen()`，并通过 `document.fullscreenElement` 跟踪状态。Electron 主进程的 Session 权限处理器只放行 `media` 和 `microphone`，其他权限统一拒绝。Electron 将 HTML Fullscreen API 归类为 `fullscreen` 权限，因此当前处理器会拒绝这次请求。

参考：

- [Electron Session 权限文档](https://www.electronjs.org/docs/latest/api/session)
- [Electron BrowserWindow 全屏事件文档](https://www.electronjs.org/docs/latest/api/browser-window)

## 2. 目标

1. 修复 Electron 桌面端 Fullscreen API 权限，使播放器可以真正进入系统全屏。
2. 保持横屏视频的非全屏页面骨架不变。
3. 横屏视频进入全屏后只显示完整视频，隐藏应用壳和学习辅助栏。
4. 竖屏视频进入全屏后使用严格双栏：左半屏视频，右半屏双语剧本。
5. 全屏过程中保持播放连续，不重新创建视频节点，不丢失进度、音量、剧本状态和滚动位置。
6. 将权限扩展限制在已信任的 Auris 桌面来源与明确的 `fullscreen` 权限，不扩大其他权限。

## 3. 非目标

- 不改变视频库页面。
- 不重新设计非全屏横屏播放器或跟读练习。
- 不裁切视频，不提供 `cover` 模式。
- 不在全屏中显示侧边栏、顶部工具栏或跟读录音区域。
- 不新增原生窗口全屏 IPC 作为自动回退。
- 不处理移动端屏幕旋转或系统方向锁定。
- 不在本次加入画中画、倍速、字幕轨切换或双屏投放。

## 4. 已确认的产品决策

### 4.1 非全屏

非全屏状态保持现有双栏骨架：

- 左栏继续包含播放器和跟读练习。
- 右栏继续显示双语剧本。
- 现有播放器尺寸、页面工具栏和侧边栏不因本功能改变。

### 4.2 横屏全屏

- 全屏画布为 `100vw × 100vh`。
- 视频使用 `object-fit: contain`，完整显示、不裁切。
- 剩余区域使用纯黑或接近纯黑的播放器舞台底色。
- 隐藏侧边栏、顶部工具栏、右侧剧本和跟读练习。
- 播放控制层覆盖在视口底部，并沿用现有自动隐藏行为。

### 4.3 竖屏全屏

采用用户在可视化比较中确认的 A 方案：

- 整个物理屏幕严格分为 `50vw + 50vw`。
- 左半屏从 `x = 0` 开始，不扣除 48px 侧边栏，也不保留侧边栏占位。
- 左半屏为黑色视频舞台；视频按高度最大化、水平居中、保持比例、不裁切。
- 控制条横跨整个左半屏，而不是只限制在狭窄的实际视频宽度内。
- 右半屏只显示双语剧本，独立纵向滚动。
- 中线使用 1px 低对比度分隔线。
- 侧边栏、顶部工具栏和跟读练习全部隐藏。

## 5. 方向判断

新增纯函数，将视频元数据归一为三种状态：

```ts
type VideoOrientation = "unknown" | "landscape" | "portrait";
```

规则：

- `videoWidth > 0 && videoHeight > 0 && videoWidth < videoHeight` → `portrait`
- `videoWidth > 0 && videoHeight > 0 && videoWidth >= videoHeight` → `landscape`
- 非有限数、零或负数 → `unknown`

方形视频归入横屏路径。元数据未加载或无效时，不猜测竖屏；进入全屏后按普通全屏播放器安全降级。元数据随后有效时，可以在同一个全屏元素中稳定切换一次布局，不退出也不重新加载视频。

## 6. DOM 与组件设计

### 6.1 单视频节点原则

进入全屏不得创建第二个 `<video>` 或把视频源复制进另一棵组件树。现有播放器、左栏和右栏保持同一套 DOM，只通过 Fullscreen API 与 CSS 原地重排。

这保证：

- 视频不会因进入全屏重新请求本地流。
- 播放时间、buffer、音量、静音和播放状态自然连续。
- 不会出现双重音轨。
- 退出全屏时无需把状态从第二个播放器同步回来。

### 6.2 全屏目标元素

将全屏目标从当前 `.video-study__player-frame` 提升为包含左右栏的 `.video-study__body` 学习画布，并为它增加专用 ref。画布写入：

- `data-fullscreen="true|false"`
- `data-video-orientation="unknown|landscape|portrait"`

实际全屏状态只以以下条件为真：

```ts
document.fullscreenElement === fullscreenSurfaceRef.current
```

不得在点击全屏按钮后提前设置成功状态。

### 6.3 建议文件边界

- `src/components/desktop/desktop-video-detail-shell.tsx`
  - 连接视频元数据、播放状态、剧本与全屏行为。
  - 将 ref 放到学习画布。
  - 记录与恢复滚动位置和焦点。
- `src/features/video-library/video-layout.ts`
  - 提供方向类型与纯方向判断函数。
- `src/components/desktop/desktop-video-detail-shell.css`
  - 保留非全屏规则。
  - 增加横屏与竖屏的 `:fullscreen` 布局规则。
- `electron/desktop-permission-policy.cjs`（建议）
  - 收敛可信来源与允许权限的纯策略，供两个 Electron Session handler 共用并独立测试。
- `electron/main.cjs`
  - 使用统一策略处理权限检查和权限请求。

不要求为了本功能拆分整个现有大组件；只提取方向判断与权限策略这两个明确、可独立验证的边界。

## 7. 状态与事件流

1. `<video>` 触发 `loadedmetadata`。
2. 同时读取时长、`videoWidth` 和 `videoHeight`。
3. 方向函数产生 `unknown`、`landscape` 或 `portrait`。
4. 用户通过全屏按钮、双击视频或 `F` 请求进入全屏。
5. 请求前记录：
   - 左栏 `scrollTop`
   - 剧本栏 `scrollTop`
   - 发起全屏的元素：按钮点击时记录该按钮；键盘或双击发起时记录播放器画布
6. 对学习画布调用 `requestFullscreen()`。
7. 只在 `fullscreenchange` 中同步 `isFullscreen`。
8. CSS 依据 `:fullscreen` 和方向属性切换布局。
9. 退出全屏后在下一动画帧恢复左右栏滚动位置，并把焦点还给发起全屏的元素；如果该元素已不在文档中，则回退到播放器画布。

监听 `fullscreenerror`，并把它与 Promise rejection 收敛到同一失败处理，避免重复反馈。

## 8. Electron 权限设计

当前权限 handler 的默认拒绝策略应保留。只对以下条件同时成立的请求返回允许：

1. 请求来源通过现有 `isTrustedDesktopOrigin(...)` 检查。
2. 权限位于明确 allowlist：
   - `media`
   - `microphone`
   - `fullscreen`

`setPermissionCheckHandler` 与 `setPermissionRequestHandler` 必须调用同一个策略，不能维护两份不同 allowlist。通知、地理位置、剪贴板、USB 等未列出的权限继续拒绝。

全屏失败不使用 `BrowserWindow.setFullScreen()` 自动回退。原生窗口全屏会把应用壳一起放大，无法自然获得“横屏只显示视频、竖屏显示视频与剧本”的元素级布局，还会引入 renderer/main 状态同步。

Electron 的 macOS 全屏转换是异步的；需要依赖 HTML 全屏事件确认状态，而不是同步读取窗口状态。

## 9. 详细视觉规则

### 9.1 全屏根画布

- 宽高：`100vw × 100vh`
- 最小宽高：`0`
- 边框与圆角：全屏时全部移除
- overflow：隐藏根画布溢出；右侧剧本自行滚动
- 外层应用底色和布局不得透出

### 9.2 竖屏左侧舞台

- 网格列：`50vw`
- 背景：`#000` 或现有播放器近黑 token
- 视频：`width: 100%; height: 100%; object-fit: contain`
- 实际 9:16 画面按高度最大化并在左半屏水平居中
- 不为实际视频宽度额外添加白色边框、圆角或阴影

### 9.3 竖屏右侧剧本

- 网格列：`50vw`
- 背景与文字沿用当前主题 token；薄荷主题保持浅暖薄荷底色
- 内边距：`clamp(32px, 4vw, 64px)`
- 正文设置合理 `max-width` 并水平居中，避免超宽屏长行
- 保留当前字体比例与中译显示状态
- 右栏设置独立滚动容器
- 无字幕时显示温和空状态，不让左侧扩展到全屏

### 9.4 播放控制层

- 竖屏下控制层宽度为整个左半屏。
- 左右安全边距为 16–20px。
- 进度条占据可用宽度。
- 下方依次保留播放/暂停、音量、时间和退出全屏。
- 播放时沿用 2.2 秒自动隐藏。
- 鼠标移动、点击、键盘操作或焦点进入时重新显示。
- `prefers-reduced-motion: reduce` 时不应用位移或布局过渡。

## 10. 交互规则

| 输入 | 非全屏 | 全屏 |
| --- | --- | --- |
| 单击视频 | 播放/暂停 | 播放/暂停 |
| 双击视频 | 进入全屏 | 退出全屏 |
| `Space` / `K` | 播放/暂停 | 播放/暂停 |
| 左右方向键 | 前后 5 秒 | 前后 5 秒 |
| `M` | 静音切换 | 静音切换 |
| `F` | 进入全屏 | 退出全屏 |
| `Esc` | 原行为 | 由 Fullscreen API 退出 |
| `R` | 开始/停止录音 | 禁用，防止启动不可见录音 |

键盘快捷键不得抢占输入框、文本域或可编辑内容。右侧剧本滚动、文本选择和右键查词继续可用。

## 11. 全屏词卡层级

现有 `FloatingWordCard` 使用 Portal 挂载到 `document.body`。HTML 全屏期间，只有全屏元素及其后代位于顶层；body 下但不在全屏元素内的弹层可能不可见。

设计要求：

- 非全屏：Portal 目标仍为 `document.body`。
- 全屏且 `document.fullscreenElement` 是 `HTMLElement`：Portal 目标改为该全屏元素。
- 退出全屏：目标恢复为 `document.body`。
- 词卡仍使用 fixed 定位、主题变量复制和现有拖动/关闭行为。

若进入全屏前已有词卡，进入时关闭它，避免 Portal 切换瞬间发生位置跳变；全屏后可重新右键打开。

## 12. 错误处理

### 12.1 全屏请求失败

如果 `requestFullscreen()` reject 或触发 `fullscreenerror`：

- 不改变播放/暂停状态。
- 清除任何乐观全屏状态。
- 不残留横竖屏全屏 CSS。
- 在播放器内部显示短暂提示：“无法进入全屏，请重试。”
- 调试日志记录错误 `name` 与 `message`，不向用户展示堆栈。
- 不复用页面顶端的大型加载错误条，避免失败反馈挤压整个学习布局。

### 12.2 元数据无效

- 方向保持 `unknown`。
- 全屏只显示普通 `contain` 视频播放器。
- 不显示空白的右侧剧本栏。

### 12.3 视频源失效

- 退出全屏。
- 沿用现有“视频播放失败，请确认文件仍可访问”反馈。
- 保留可恢复的剧本与页面状态。

### 12.4 剧本缺失

- 竖屏全屏仍保持严格 50/50。
- 右侧显示：“这个视频还没有对应的台词 / 字幕。”
- 不自动让视频扩展为全屏，以免布局在同一竖屏视频上不稳定。

## 13. 测试计划

### 13.1 单元测试：方向判断

- `1920 × 1080` → `landscape`
- `1080 × 1920` → `portrait`
- `1080 × 1080` → `landscape`
- `0 × 0`、`NaN`、负数 → `unknown`

### 13.2 React 组件测试

- 元数据加载后写入正确方向属性。
- 全屏请求目标是学习画布，而不是播放器卡片。
- `fullscreenchange` 发生后才更新状态与按钮文案。
- 横竖屏切换前后始终只有一个 `<video>`。
- 进入/退出不重置时间、音量、静音和播放状态。
- 请求拒绝时显示播放器内提示且不残留状态。
- 全屏时 `R` 不触发录音。
- 竖屏全屏中剧本可以滚动与查词。
- 词卡挂载到 `document.fullscreenElement`。
- 退出后恢复焦点与滚动位置。
- 快速连续切换不会让按钮和实际全屏状态分离。

### 13.3 Electron 权限策略测试

- 可信 Auris 来源允许 `fullscreen`。
- 可信来源继续允许 `media` / `microphone`。
- 非可信来源拒绝上述权限。
- 即使顶层 `webContents` 可信，不可信的 requesting origin 或跨域子框架仍拒绝上述权限。
- 未列出的权限默认拒绝。
- 权限检查与权限请求使用同一策略。

### 13.4 Playwright 布局测试

竖屏全屏：

- 左栏 `x = 0`。
- 左栏宽度为视口的 50%，误差不超过 1px。
- 右栏 `x = 50vw`，宽度为剩余 50%。
- 侧边栏、顶部工具栏和跟读练习不可见。
- 视频计算样式为 `object-fit: contain`。

横屏全屏：

- 播放器边界等于整个视口。
- 剧本、侧边栏、顶部工具栏和跟读练习不可见。

两种方向都需在 1160px、1440px、1920px 宽度下验证。增加快速双击 `F`、无剧本、无效元数据、请求拒绝和 reduced-motion 边界探针。

### 13.5 真实 Electron 验证

浏览器或 jsdom 中模拟 `requestFullscreen()` 不能证明 Electron 权限已经修复。完成前必须在 macOS Electron 运行环境执行一次真实验证：

1. 打开真实横屏本地视频，播放中进入全屏并退出。
2. 打开真实竖屏本地视频，确认严格 50/50 与侧边栏完全隐藏。
3. 验证 `F`、双击、按钮和 `Esc`。
4. 验证进入/退出时播放连续、无第二路声音、剧本位置可恢复。
5. 验证全屏右栏的滚动和右键查词。

## 14. 验收标准

以下条件全部满足才算完成：

1. macOS Electron 中横屏和竖屏均能真正进入、退出 HTML 全屏。
2. 不再出现截图中的“无法进入全屏模式”。
3. 横屏视频的非全屏页面骨架无视觉回归。
4. 横屏全屏只显示完整视频。
5. 竖屏全屏严格执行 `50vw + 50vw`，左栏从屏幕 `x = 0` 开始。
6. 全屏不显示 48px 侧边栏及其占位。
7. 全屏切换不创建第二个视频节点，不重置播放状态。
8. 右侧双语剧本可滚动、可查词，缺失时有空状态。
9. 退出全屏后滚动位置、焦点、进度、音量和静音状态正确。
10. 非可信来源和未列出的 Electron 权限仍被拒绝。
11. 相关 Vitest、Playwright、lint 通过。
12. 已记录一次真实 Electron 运行验证结果。

## 16. 风险与控制

- **风险：Electron 权限放行过宽。** 通过可信来源检查与固定权限 allowlist 控制。
- **风险：全屏时复制播放器导致状态丢失。** 坚持单视频节点与原地 CSS 重排。
- **风险：Portal 在全屏顶层不可见。** 全屏时切换词卡 Portal 目标。
- **风险：macOS 异步切换造成按钮状态错误。** 只依赖 `fullscreenchange` / `fullscreenerror`。
- **风险：现有播放器文件有未提交改动。** 实现时采用小范围补丁，保留当前主题与词卡相关变更，不覆盖用户工作。
- **风险：自动化测试在浏览器通过但 Electron 仍失败。** 把真实 Electron 验证列为硬性完成条件。

## 17. 最终决策摘要

- 横屏：非全屏骨架不变；全屏后只显示视频。
- 竖屏：全屏后左半屏视频、右半屏双语剧本。
- 侧边栏：全屏完全隐藏，不保留位置。
- 比例：严格 50/50，不采用 44/56 或留边画框。
- 技术：HTML Fullscreen API + 可信 Electron `fullscreen` 权限。
- 连续性：同一个视频节点原地重排。
- 验证：自动化测试加真实 macOS Electron 运行证据。
