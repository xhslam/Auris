# 应用主题统一与夜间黑白配色

## 请求与边界

用户要求先定位跨页面颜色混杂的原因，再让每个主题使用少量统一颜色，并明确夜间主题只使用黑白灰强调色。保留六个主题入口、现有页面布局、知识点数据、笔记内容以及人生阶段动画；不改变用户主动选择的文章阅读专用主题或原始媒体颜色。错误、警告、成功状态仍保留语义颜色，不作为页面品牌色。

## 已确认问题

- `globals.css`、`auris-theme.css`、`auris-redesign.css` 分别遗留橙色、粉橙色与金色令牌；旧组件与新组件读取不同变量。
- Review 拥有独立强调色并重新定义 `--accent`，导致同一个夜间主题下外壳金色、复习页青色。
- 侧栏另用蓝色图标与红色选中标记，首页日历及人生路径保留棕金色。
- Nia 可保存独立橙/金/蓝偏好；独立浏览器另存一套 CSS 颜色定义。
- Focus 与 Assessment 使用固定黑金内联样式，不在主题外壳内。
- 页面外层 portal 缺少应用主题边界，可能落回旧的根令牌。

## 实现

`globals.css` 的六套调色板成为外壳、独立浏览器、文档根节点的共同来源。夜间：背景 `#151515`、内容面 `#252525`、主文字/强调 `#f5f5f5`、辅助文字 `#b5b5b5`、主按钮文字 `#161616`。背景与内容通过明度、边框分层。

新增 `src/styles/app-palette.css`，将 legacy 与 `--auris-*` 名称映射到当前 `--app-*` / `--accent`。Home、Notes、Reading 默认阅读模式、Review、Nia、视频详情原有局部色表改为引用。侧栏与日历使用同一强调色，夜间人生场景与路径改为灰阶；Focus/Assessment 接入 DesktopAppFrame。Nia 外观统一跟随应用，忽略旧独立强调色偏好并移除相关选择按钮。`use-app-theme.ts` 为 portal 同步文档根主题。

## 验证

- 13 个定向单元/组件文件合计 151 项：首轮仅旧蓝色场景断言失败，改成灰阶验证后该文件 8 项通过；随后最终首页/配色/人生场景回归 5 文件 71 项通过。
- 新增 Playwright `tests/e2e/app-palette.spec.ts`：11 路由逐一切换六主题，验证全局/页面/portal 强调色一致，正文、辅助字、强调色在背景与内容面、主按钮字色达到 4.5:1。生产服务器上 11 项全部通过。
- 定向 ESLint、`git diff --check` 通过；第一轮生产构建和运行时隐私审计通过。最终收尾修改另行构建打包。

## 验证限制

浏览器巡检主要覆盖路由入口与主题切换，视频详情有组件回归但未用用户视频执行完整播放/字幕流程。原始媒体、文章主动指定的阅读主题和警告语义色不纳入“界面单一强调色”的约束。
