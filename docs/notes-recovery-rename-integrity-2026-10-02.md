# Auris 1.0.14：笔记恢复与重命名完整性修复

用户报告在设置中更新 Codex CLI 配置后，笔记正文消失。现场磁盘文件确实只有标题（36 字节）；这不是仅凭截图推断的显示异常。热退出记录保留了旧文件名下的完整原文，用户确认内容和旧文件名一致。正常退出应用、备份现场后，按原文恢复到当前文件名，195 行、11,993 字节，SHA256 为 `d39cad67a1ed3495bcde435dcb8382f8aaffd1e36b31f24b3e60b235a45e1991`。恢复记录与工作区的旧路径同步迁移，迁移前快照保留在本地忽略的 `release/recovery-20261002-codex-config/`，没有将用户笔记内容写入仓库。

调用链复核确认设置按钮直接调用 MCP 安装 IPC；Codex 安装器写入 CLI TOML 配置及受管凭据，不直接调用笔记保存、重命名或清空逻辑。目前缺少能把按钮点击与本次磁盘覆盖直接联系起来的日志，不能把时间先后当作已证明的因果。

独立回归复现了重命名的三项严重缺陷：磁盘只有占位正文而编辑器有完整未保存正文时，重命名会使用旧磁盘正文并清掉草稿；保存失败时仍然移动文件；重命名 IO 等待期间的新编辑被清除。旧的 `clearPendingSave` 只删除 Promise 跟踪，不能取消正在执行的物理写入。这些是已验证的缺陷，但尚不能证明是本次事故的唯一触发链。

修改共用的 Notes workbench 保存和动作层：重命名等待已有保存完成，保存相关草稿后重建索引；保存失败或仍有更新的编辑则停止。操作期间暂停相关路径的新保存，结束后重新调度。沿用既有标题/Wiki link 规划、磁盘基线校验和历史存储；写入前复核基线，不再盲目覆写。重命名完成或部分失败后迁移真实路径、磁盘基线、后续编辑和恢复草稿，保留未落盘内容；新路径恢复捕获失败不会删除旧路径的恢复副本。目标碰撞同时考虑磁盘文档和当前打开的恢复文档。

实际安装包冷启动进一步发现第二项可复现缺陷：Vault 路径已配置但初始目录快照尚未完成时，恢复逻辑把空快照当作文件不存在，设置 `isMissing` 并关闭自动保存。界面因此长期显示“保存中”，尽管磁盘文件已存在。新增测试在修复前明确失败；恢复分类现在等待匹配当前 Vault 根目录的首次有效快照，仍保留真正缺失文件必须手动保存才能重建的原有保证。

实机验收暴露初始快照等待规则的最强反例：`loadDocuments()` 原先绕过 `refreshChain`，能在目录扫描未完成时提前发布带当前时间和根目录的空快照。单凭根路径和时间无法证明扫描完成。额外修复共用 Vault 索引层，让按需加载复用原有串行队列，第一次调用必须先取得真实目录清单。两个队列回归在修复前失败、修复后通过。文件缺失判定改用目录 entries，而非仅用 lazy documents cache；目录已知存在但读取尚未完成时延后恢复分类，实际读到文件后解除旧的 missing 状态。新增回归同时确认该场景不会阻断自动保存。

对照固定上游 [VMark v0.9.90](https://github.com/xiaolai/vmark/tree/662d73d46d2ed6294d087ad1ced30223384de170) 的 [renameFile.ts](https://github.com/xiaolai/vmark/blob/662d73d46d2ed6294d087ad1ced30223384de170/src/services/persistence/renameFile.ts)、[applyPathReconciliation.ts](https://github.com/xiaolai/vmark/blob/662d73d46d2ed6294d087ad1ced30223384de170/src/services/persistence/applyPathReconciliation.ts) 和 `saveToPath.ts`，采用其“迁移文档身份并保留 live buffer”的保证，适配 Auris 的 React hook、Vault client 与 Electron 恢复存储，没有引入 Tauri 或重造保存框架。

验证：重命名新回归 9 项通过，覆盖原场景、失败、迟到编辑、在途保存、移动后写入失败、缺失源、dirty 引用、外部变更及目标碰撞；新增启动恢复和 Vault 队列回归通过。Notes 单元和组件最终回归 131 文件、1,091 项通过。一次默认并发回归出现终端 pipe 输入时序测试失败，单独复测该文件 21 项通过，降低到 2 个 worker 后整组通过；未以此追加无关终端改动。MCP 安装器与配置 22 项通过，定向 ESLint 和 diff 空白检查通过。生产构建与三个 Markdown 补丁产物门禁、桌面装配隐私审计通过。顺手修复修改测试内既有的 mock、literal 与 callback 类型推断，全仓 TypeScript 从 250 减至 247 项既有错误，本轮改动文件无错误；构建成功不替代全仓类型检查。

边界：现有 Vault read/compare/write 是应用级基线校验，不能对不遵守同一协议的外部编辑器提供文件系统级原子 CAS；多文件 Wiki link 改写也不是文件系统事务。部分失败保留真实路径和完整草稿并报告错误。没有发布 GitHub Release。

## 1.0.15：旧名称与离开页面时的完整性复查

进一步读取事故前的私有快照确认：2026-09-27 07:34:05 UTC 的完整草稿正文首行已经是 `# 对数稳定判据的 10 道习题`，但持久化恢复键仍为 `study-note-202.md`。该名称符合现有新建笔记的 `Study Note <计数>` 文件命名规则；正文标题与物理路径原本独立，自动同步在正文保存完成后才执行，并受“本次会话编辑过”和失败去重规则约束。因此不能据旧路径否认用户已改标题，也不能证明历史上的具体哪一步没有完成文件身份迁移。当前物理文件使用中文名称，旧物理路径不存在；恢复原文哈希保持不变。

新增失败注入测试在本轮修复前明确复现四项缺口：

1. 第一笔输入立即捕获，400ms 内的后续输入暂存在 recovery window；离开 Notes 的 cleanup 原先取消定时器并直接清空 pending draft，导致最新输入没有进入持久恢复存储。现在先捕获最后一份 pending draft，再清空窗口；捕获返回 false 也作为恢复失败反馈，而非只处理抛出的异常。
2. 保存后的草稿清理存在异步 IO；清理等待期间的新输入原先被旧保存的 React dirty setter 错误地清除。现在清理后重新检查最新 live buffer 和 save claim，保留新输入的 dirty 状态并重新触发保存。
3. 恢复存储的 clear 原先仅按 vault/path 删除，旧保存可以清掉同一路径下的新草稿。沿用主进程既有串行 mutation queue 和原子 JSON 写入，只扩展可选的 expectedRawSource 条件；在队列内比较当前草稿，匹配本次实际保存的原文才删除。renderer 本地回退也使用同一规则，IPC 验证可选条件类型。
4. 工作区路径持久化原先完全依赖后续 React effect；重命名在跳转设置后完成时，卸载组件的 setState 不会执行该 effect，留下旧路径。现在动作的 setter 直接捕获工作区，并用同步 ref 顺序计算更新；已卸载时也能完成身份持久化。首次工作区加载未完成时的用户操作排队，切换 vault 后的旧回调不会污染新 vault。

路径动作复查还发现原文件/文件夹移动与目录改名绕过草稿保存、live buffer 和恢复键迁移。现在复用同一 runDocumentMutation 与路径 reconciliation：等待所有相关子文档的在途保存，刷新磁盘基线，保存失败或目标碰撞则停止；保留 IO 等待期间的新输入并迁移到对应新路径。目录名称拒绝路径分隔符、NUL、`.` 和 `..`。恢复迁移使用 Promise 结果确认，先捕获新身份再条件清除旧草稿；失败仍保留原副本。完成 rename 仅迁移工作区已有位置，不抢回用户已切换到的其他笔记；旧/新路径同时存在于工作区时去重。

另外修复“标题已经正确，但文件名仍为默认名”时，手动重命名提交同一标题会被直接忽略的分支。自动标题同步的失败去重仅阻止连续渲染重试，之后的明确编辑会允许再次尝试。不会仅因打开历史笔记而改动其文件名或正文。

继续对照固定上游 VMark 的 renameFile/applyPathReconciliation，复用其完整身份迁移与保留实时正文原则；没有引入第二套编辑器或存储系统。新增覆盖包括移动中输入、目录下多份 dirty 草稿、保存失败、同标题修复路径、延迟工作区加载、跨 vault 回调、路径别名去重与原子条件清理。

最终验证：Notes 单元、Notes 组件及 Electron notes 恢复存储 134 文件、1,132 项通过；定向 ESLint、CJS 语法与 git diff --check 通过；桌面 IPC 合约 126 invokes / 129 handlers 通过。生产构建和桌面装配隐私审计通过。全仓 TypeScript 仍有 247 项既有错误，修改文件不在清单。一次与 Next 构建并发的类型检查遇到生成的 .next/types 被重建，已在构建完成后重跑，不将该次输出作为有效类型基线。
