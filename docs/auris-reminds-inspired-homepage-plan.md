# Auris 首页 / 主界面改造计划（借鉴 reminds 产品气质）

> 本轮只做计划，不修改任何代码。文档基于对当前 Auris 仓库的实际阅读，给出可直接进入实现的方案。
> 设计目标：让 Auris 首页拥有 reminds 那种「极简、专业、干净、留白充足、入口清晰」的成熟 AI 知识管理桌面应用气质。
> 重要约束：只借鉴 reminds 的**交互结构、视觉节奏、信息层级、产品气质**，不复制其品牌名、Logo、文案、插画、图标素材或专有资产。最终成品必须是 Auris 自己的品牌版本。

---

## 0. 阅读到的现状速览（事实层）

以下是改造计划的依据，均来自当前仓库代码。

**技术栈**：Next.js 16（App Router）+ Electron 桌面壳 + Supabase。`package.json` 描述仍是「Auris — language learning through listening and shadowing」。

**首页入口链路**：

- `src/app/page.tsx` → 渲染 `DesktopHomeShell`
- `src/components/desktop/desktop-home-shell.tsx`（首页主体，标题 "Continue Today" / "Rehearsal"）
- 所有页面被 `src/components/desktop/desktop-app-frame.tsx` 包裹（提供侧边栏 + 主视口 + 右侧 AI Dock）
- 侧边栏：`src/components/desktop/desktop-app-sidebar.tsx`
- 导航数据：`src/components/desktop/desktop-shell-fixtures.ts`

**当前路由**（`src/app/`）：`/`（首页）、`/notes`、`/reading`、`/rehearsal`、`/video`、`/workspace`（含 `?view=chat` 加载 `HomeDashboardV2`）。**目前没有**独立的「闪念 / 快速捕捉」「每日回顾」「AI Pilot」路由。

**侧边栏现状**：图标轨道式，宽度仅 `74px`，**默认隐藏、鼠标移到左缘 24px 触发区才展开**（`DesktopAppFrame` 里的 reveal-zone 逻辑）。只有图标，没有头像、VIP、统计、活跃日历。分组为 primary（Dashboard、AI Coach）/ library（Meeting Clips、Reading）/ tools（Rehearsal Workspace、Notes）。

**主题与样式**：`src/app/globals.css` 是**单一巨型文件（约 331KB，112 个 CSS 变量，多套主题块）**。默认是**深色**主题（`--bg: #090607`，橙色强调 `--accent: #ff7b45` / `--accent-strong: #ff4d6d`），后面又有浅色覆盖块；notes 模块是独立的绿色主题（`--notes-bg: #edf3e8`）；desktop 画布是浅灰 `#f5f8fc`。整体视觉系统**不统一**。

**可复用基础组件现状**：几乎没有通用原子组件。只有零散的 `meeting-drill-empty-state.tsx`、`question-card.tsx`、`desktop-video-card.tsx`、`desktop-showcase-card.tsx`。**没有**通用 `Button` / `Card` / `EmptyState` / `FloatingActionButton`。notes-v2 有一整套工作台组件，ai-dock 有独立 shell。

**历史包袱**：`desktop-shell-fixtures.ts` 里残留大量「Enjoy」App 的假数据（`COMMUNITY_TOPICS`、`COMMUNITY_RANKING`、课程卡片等），说明首页是从早期模板演化而来，定位漂移。

## 1. 当前 Auris 首页现状分析

### 1.1 核心问题

**产品定位与首页叙事脱节**。首页标题是 "Continue Today / Rehearsal"，文案围绕「英语跟读、会议演练、慢速 TTS」，但项目真正的核心能力已经长成「阅读工作台 + Markdown 笔记 + AI 助手 + 学习记忆」。首页讲的是旧故事，没有体现 Auris「阅读 → 摘录 → 理解 → 笔记 → 回顾 → AI 辅助」的知识管理闭环。

**信息定位单薄且割裂**。首页只有一个 Hero 面板 + 一个「快捷操作」四宫格，缺少「最近笔记 / 今天继续阅读 / 今日回顾状态 / 最近项目」这类知识工作台应有的当下入口。同时仓库里还残留 Enjoy 社区排行榜等无关假数据，定位混乱。

**导航不专业、可发现性差**。侧边栏默认隐藏、靠 hover 才出现，且只有 6 个图标、无文字标签、无用户区。这对一个「长期使用的知识管理桌面应用」是反模式——reminds 的固定侧边栏始终在场、信息分层清晰，可发现性和专业感都明显更强。

**视觉风格不统一**。默认深色橙调的首页、绿色的 notes、浅灰的 desktop 画布三套观感并存，缺少统一的品牌色、间距、卡片、圆角、阴影规范。第一眼无法形成「这是一个成熟产品」的整体印象。

**功能虽不算堆叠，但入口设计零散**。首页四个快捷操作（转成训练 / 慢速 TTS / 笔记摘要 / AI 助手）仍是旧能力导向，没有围绕新核心模块组织。

### 1.2 保留 / 弱化 / 移除建议

| 处理                 | 内容                                                  | 理由              |
| ------------------ | --------------------------------------------------- | --------------- |
| **保留**             | `DesktopAppFrame` 的整体壳结构（侧边栏 + 主视口 + AI Dock）       | 架构合理，是改造地基，不重写  |
| **保留**             | 路由分发方式（App Router 各 `page.tsx` 套 `DesktopAppFrame`） | 成熟稳定，新页面沿用同一模式  |
| **保留**             | 已有的功能页：notes-v2、reading-workbench、workspace、ai-dock | 核心能力，绝对不动其内部逻辑  |
| **保留**             | 首页的加载骨架屏、reduced-motion 处理、路由 prefetch              | 体验细节做得不错        |
| **弱化**             | 首页的「Rehearsal / 跟读演练」叙事                             | 降为众多入口之一，不再做主标题 |
| **弱化**             | 侧边栏的 hover-reveal + 大量粒子/ripple 动效                  | 改为常驻、克制；动效收敛    |
| **移除（仅删假数据，不删功能）** | `desktop-shell-fixtures.ts` 中的 Enjoy 残留（社区、排行榜、课程卡） | 与定位无关的死数据       |
| **重构（视觉，不动逻辑）**    | 首页 Hero 四宫格 → 知识工作台 Dashboard                       | 体现真正闭环          |

## 2. reminds 主界面结构拆解（基于官网与 4 张桌面截图）

> 注：以下是对 reminds 「设计方法」的客观拆解，用于指导 Auris 自有实现，不作素材复制。

**整体骨架**：固定左侧栏（约 240–260px）+ 右侧主内容区。永远是「左导航 + 右内容」两栏，主内容随模块切换，左栏不动。

**左侧栏自上而下的信息分层**（这是 reminds 专业感的核心）：

1. **用户信息区**：圆形头像 + 昵称 + VIP 徽标。建立「这是我的空间」的归属感。
2. **数据统计区**：三个并排大数字 + 小标签（笔记 12 / 回顾 0 / 天数 1）。轻量、不喧宾夺主。
3. **活跃日历区**：圆点热力网格（4 月—6 月），当天高亮为实心主色圆点。把「持续使用」可视化。
4. **主导航菜单区**：线性图标 + 中文文字标签（笔记、闪念、每日回顾、MindPilot），激活项用主色文字 + 主色图标。条目少而精。

**右侧主内容区的几种形态**：

- **卡片网格（笔记页）**：2–3 列卡片瀑布。卡片含：时间戳、标题、标签（胶囊）、正文摘要、右上角「…」更多按钮。第一张可置顶（图钉）。
- **极简列表（闪念页）**：仅少量卡片，大面积留白，单条卡片只承载一段文字 + 时间 + 更多按钮。强调「轻」。
- **空状态（每日回顾页）**：标题下方一条主色细分割/进度线 → 居中插画 → 一句克制文案（如「从明天开始回顾」）。不啰嗦、不堆按钮。
- **AI 工作台（MindPilot 页）**：居中品牌标题 → 一个大输入框（带「@笔记 #标签 /技能」提示）→ 下方一排功能胶囊按钮（玩转 / 看见自己 / 复盘前行 / 写成作品 / 灵感漫游）→ 「近期项目」区（含「+ 新建项目」卡）。像 AI 工作台，但很轻，不像复杂后台。

**顶部工具区**：页面标题 + 视图/布局切换 + 标签筛选（#）+ 搜索图标。轻量，靠右排布。

**悬浮新增按钮**：右下角固定、圆形、主色（紫）、白色「+」。所有列表型页面都保留。

**主色（紫）的用法**：克制点缀。只用在——激活态导航、当天活跃圆点、回顾页细线、FAB、主按钮、个别强调链接。大面积仍是白 / 极浅灰白底。

**视觉语言**：纯白 / 极浅灰背景；卡片白底 + 极浅描边 + 大圆角（约 12–16px）+ 极轻或无阴影；标题深色清晰、正文克制、辅助文字浅灰；线性图标统一尺寸；留白充足，行距舒展。

## 3. Auris 首页 / 主界面拟改造方案

> 总原则：**沿用现有 ********************************`DesktopAppFrame`******************************** 地基**，把「图标 hover 轨道」升级为「reminds 式常驻信息侧栏」，并把首页从「跟读演练」重塑为「今日知识工作台」。所有子页统一卡片/按钮/空状态语言。

### A. 左侧 Sidebar（改造 `DesktopAppSidebar`，不新建并行侧栏）

**定位（已按你的偏好确定）：保持现有窄图标侧栏的宽度常驻，展开时再放大；详情页可收缩。** 具体两种状态、两类页面：

- **窄态（常驻默认）**：就是现在这条 74px 图标轨道，宽度不变，但**改成始终在场、不再藏起来靠 hover 才冒出来**。平时只显示图标。
- **宽态（展开放大）**：触发后（hover 或点一个固定/展开按钮）侧栏**横向放大**，露出完整信息层——头像 + 名称、统计数字、flomo 圆点热力日历、导航的文字标签、底部设置。鼠标移开或再点一下收回窄态。也就是说，下面第 2、3 区（统计、活跃日历）和导航文字标签都只在「宽态」里显示，窄态只留图标。
- **列表/总览类页面**（首页、笔记网格、闪念、每日回顾）：窄态常驻，可随时展开放大。
- **详情类页面**（阅读工作台、笔记编辑器、视频详情等内容页）：**侧栏不需要常驻**，可展开、可完全收起，把空间让给正文。

`DesktopAppFrame` 现有的 reveal-zone / hide-delay 逻辑保留并改造为上面的「窄态常驻 + 展开放大 / 详情页可收起」，不再是「默认完全隐藏」。

**展开后的具体显示（自上而下，给出可实现的视觉细节）：**

1. **Auris 用户 / 项目标识区**：左侧圆形头像（Auris 自有 wordmark，非 reminds 标记）+ 右侧名称（单行，semibold）+（可选）一枚浅底徽标（本地/同步状态或会员标识）。一行高度约 56–64px，下方一条极浅分割线。复用现有 `ShadowingMark` 的位置，替换为 Auris 品牌标记。

2. **简洁统计区**：一行四个「大数字 + 小标签」并排（数字 18–20px semibold、标签 11–12px 浅灰），克制不喧宾夺主——
   - 笔记数量（来自 notes storage）
   - 阅读材料数量（reading 库）
   - 回顾次数（daily review）
   - 连续学习天数（streak）

3. **flomo 式圆点活跃热力日历**：近 \~3 个月的圆点网格（7 行 × 周列），**记录越多颜色越深**——按当天活跃量（笔记 + 闪念 + 回顾等条数）映射到 Auris 主色的 5 级深浅阶梯：

   - 0 条：`--auris-heat-0`（极浅灰，空槽）
   - 1–2 条：`--auris-heat-1`（主色 \~15% 透明度）
   - 3–4 条：`--auris-heat-2`（\~35%）
   - 5–7 条：`--auris-heat-3`（\~60%）
   - 8+ 条：`--auris-heat-4`（主色实心）

   当天再加一圈主色描边以示「今天」。底部标注月份刻度（如 4 月 / 5 月 / 6 月）。hover 圆点显示当天日期 + 条数 tooltip。数据先用本地统计/占位，后续接真实活跃记录。这种「连续记录可视化 + 深浅热力」是 flomo / reminds 都用、且显专业的表达，正是你想要的效果。

4. **主导航**（线性图标 + 文字标签，常驻可见、激活态用 Auris 主色）：
   - 首页 / 工作台 → `/`
   - 笔记 → `/notes`
   - 闪念 / 快速捕捉 → `/flash`（新增）
   - 每日回顾 → `/review`（新增）
   - 阅读工作台 → `/reading`
   - （保留但下沉）Meeting Clips、Rehearsal Workspace 归入「工具」次级分组，避免喧宾夺主
   - AI 入口**不新建独立页面**：沿用现有右侧 AI Dock（及 `/workspace?view=chat`），需要时唤起即可

5. **底部设置入口**：齿轮图标 + 「设置」，固定在侧栏底部 → `/settings`（或打开现有 settings 面板）。

要求：侧栏干净、条目精简；图标统一线性风格、统一尺寸；激活态用 Auris 主色（文字 + 图标 + 左侧主色指示条）；hover 态收敛（去掉过度粒子/爆裂动效，保留轻微背景高亮）。

### B. 首页 / 工作台（重塑 `DesktopHomeShell`）

不做成官网宣传页，而做成桌面应用的「今日工作台」。区块（全部轻量卡片、强留白、少文字）：

1. **顶部简短欢迎语**：如「晚上好，继续今天的阅读与思考」（按时段 + 用户名，单行，无大 Hero）。
2. **今日继续阅读**：1 张主卡，展示上次阅读材料 + 进度，点击回到 reading workbench。
3. **最近笔记**：2–3 张笔记卡（复用统一 `NoteCard`），来自 notes storage。
4. **快速捕捉入口**：一行轻输入框或一张「+ 记录闪念」卡 → 进入 `/flash`。
5. **AI 帮我理解 / 总结 / 整理入口**：2–3 个胶囊按钮，**唤起现有右侧 AI Dock** 并预填意图（不跳新页面）。
6. **今日回顾状态**：一张小卡，有待回顾则显示数量 + 进入按钮，无则显示克制提示。
7. **最近项目 / 知识主题**：横向卡片，含「+ 新建」。

整体像 reminds 一样克制：少文字、强留白、卡片轻。

### C. 笔记页（视觉对齐，逻辑不动）

借鉴 reminds 卡片网格，但**不重写 notes-v2 工作台逻辑**——本计划针对的是 notes 的「卡片网格总览」呈现层（若现状是文件树编辑器，则新增一个「卡片总览」视图作为 `/notes` 的入口形态，编辑器作为下一层）：

- 顶部：标题 + 布局切换 + 标签筛选（#）+ 搜索
- 主体：2–3 列 `NoteCard`，含 更新时间 / 标题 / 标签 / 摘要 / 「…」更多
- 右下角悬浮新增按钮（`FloatingActionButton`）

### D. 闪念 / 快速捕捉页（新增 `/flash`）

借鉴 reminds 闪念页：少量卡片展示快速想法；支持一键「转成正式笔记」（调用现有 notes 创建能力）；空状态极简；**不做复杂编辑器**，只做轻输入 + 卡片列表 + FAB。

### E. 每日回顾页（新增 `/review`）

借鉴 reminds 回顾空状态：顶部标题 + 一条 Auris 主色细进度线；有内容显示「今日待回顾」卡片；无内容显示居中 `EmptyState`（Auris 自有插画 + 一句克制文案，如「从明天开始回顾」的同气质但自有文案）。

> 说明：**不新增独立 AI 助手 / Pilot 页面**（按你的要求）。AI 能力沿用现有右侧 AI Dock，首页的 AI 胶囊按钮唤起 AI Dock 即可，不再做 `/pilot` 路由与页面。

## 4. 视觉风格规范（Auris 自有品牌版）

| 维度                   | 规范                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **背景**               | 白色或极浅灰白（如 `#FBFBFD` / `#F6F7FB`），告别当前深色橙调首页                                                                                                                                                                                                                        |
| **主色（已定：落日 Sunset）** | Auris 自有主色，**橘→粉签名渐变**风格。纯色 `--auris-primary: #FF5C72`、强调态 `--auris-primary-strong: #E03E63`、浅底 `--auris-primary-soft: rgba(255,92,114,0.12)`；签名渐变 `--auris-gradient: linear-gradient(135deg, #FF7A59, #FF3D77)`。渐变只用于品牌标记 / FAB / 激活态等少数强调处，其余强调用纯色，大面积仍是白 / 极浅灰。 |
| **侧边栏**              | 白底 + 轻分割线（`rgba(20,20,40,0.06)`）。**窄态常驻（宽度同现在 74px，仅图标），展开时横向放大露出信息层；详情页可收起。** 激活项左侧主色指示条 + 主色图标文字 |
| **卡片**               | 白底、浅描边（1px `rgba(20,20,40,0.07)`）、圆角 **12–16px**、极轻阴影或无阴影；hover 轻微抬升/描边加深                                                                                                                                                                                          |
| **字体层级**             | 标题清晰（深墨 `#1B1B2A`，semibold）；正文克制（`#3A3A4A`）；辅助文字浅灰（`#8A8A99`）                                                                                                                                                                                                      |
| **图标**               | 统一线性风格、统一描边宽度（1.8）与尺寸（20–24px）；激活态填主色                                                                                                                                                                                                                              |
| **按钮**               | 少量使用；主按钮实心主色 + 白字；次要按钮做胶囊形（浅底/描边）                                                                                                                                                                                                                                  |
| **悬浮新增按钮**           | 右下角固定、圆形、填 `--auris-gradient`（落日橘→粉渐变）、白色「+」、轻阴影                                                                                                                                                                                                                   |
| **活跃热力色阶**           | flomo 式 5 级深浅（记录越多越深），由落日纯色 `#FF5C72` 派生：`--auris-heat-0: #ECECEF`（空槽）/ `-1: rgba(255,92,114,0.20)` / `-2: rgba(255,92,114,0.42)` / `-3: rgba(255,92,114,0.66)` / `-4: #FF5C72`；当天加主色描边                                                                            |
| **空状态**              | 可选 Auris 自有简洁插画 + 一句克制文案；不花哨                                                                                                                                                                                                                                       |
| **间距**               | 建立间距阶梯（4 / 8 / 12 / 16 / 24 / 32 / 48），区块间大留白                                                                                                                                                                                                                      |
| **整体感受**             | 专业、安静、轻盈，适合长期使用                                                                                                                                                                                                                                                    |

**统一配色（重点）**：reminds 之所以显专业，关键在于**全局只有「一套」配色语言**——白/极浅灰底 + 单一主色克制点缀 + 三级文字灰阶，所有页面、所有组件共用同一组变量，不存在「首页一套、笔记一套、画布一套」的割裂。Auris 要达到同样效果：**全站收敛为一套 ****************************`--auris-*`**************************** token**（主色、热力色阶、文字灰阶、卡片描边、圆角、阴影、间距），首页 / 笔记 / 闪念 / 回顾 / 阅读 / 侧栏 / AI Dock **全部引用同一组变量**，主色只用于激活态、当天活跃点、回顾细线、FAB、主按钮等少数强调处，其余大面积留白。这是把当前「深色橙 + 绿 notes + 灰画布」三套观感拉齐为一套的核心动作。

建议把上述统一为一组新的「Auris 设计 token」（见 §5），与既有 `--accent`（橙）并存而非直接覆盖，逐页迁移，避免一次性改动 331KB 全局样式引发连锁回归。

:root {

  --auris-heat-2: rgba(255, 92, 114, 0.42);
  --auris-heat-3: rgba(255, 92, 114, 0.66);
  --auris-heat-4: #FF5C72;

  /* 中性体系 */
  --auris-bg: #FBFBFD;               /* 画布 */
  --auris-surface: #FFFFFF;          /* 卡片/侧栏 */
  --auris-line: rgba(20, 20, 40, 0.07);   /* 描边/分割线 */
  --auris-text: #1B1B2A;             /* 标题 */
  --auris-text-secondary: #3A3A4A;   /* 正文 */

## 6. 风险控制

- **本轮只写计划，不改代码。**
- 不删除任何现有功能；清理仅限 `desktop-shell-fixtures.ts` 中确认无引用的 Enjoy 死数据（删前先 grep 确认零引用）。
- 不破坏 notes、reading workbench、AI assistant、editor 等已有模块——所有改造止于「呈现层 / 入口层」。
- 不大范围重构项目架构；沿用 `DesktopAppFrame` + App Router 现有模式。
- 不复制 reminds 的文案、素材、Logo、品牌元素；只借鉴设计方法与产品结构。
- **最大技术风险**：`globals.css` 是单一 331KB 巨型文件、含多套主题与大量作用域覆盖。直接全局换色/换布局极易引发跨页回归。**对策**：新增独立 token 区块与组件样式、逐页迁移、改一页验一页；不动既有选择器块。
- **次级风险**：侧栏改「窄态常驻 + 展开放大」后，展开瞬间会临时占用更多横向空间，需回归各页布局（尤其 notes-v2、reading 多栏）。**对策**：窄态常驻只占现有 74px 不影响布局；展开为浮层覆盖式放大（不挤压正文）或在详情页直接收起，窄窗自动收起。
- 若发现首页 / 路由结构比预期复杂，先在对应 PR 描述中说明风险，再按下方分阶段推进，不跳步。
