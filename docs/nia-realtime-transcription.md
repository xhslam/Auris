# Nia 实时转写

## 使用

1. 打开 Nia，在左侧「会话记录」旁选择「实时转写」。这一步只切换界面，不自动开启麦克风；若正在语音对话，会先结束旧会话。
2. 阅读云端识别提示，并确认已征得在场谈话者同意，点击「开始转写」。
3. 识别中的文字实时显示，确认后的段落自动写入本机 Nia 历史，来源标记为 `transcription`，列表以「转写」区分。
4. 「暂停」停止发送麦克风声音；「继续转写」恢复。「结束转写」立即停止麦克风采集，保留连接约 1.8 秒接收尾句，然后释放连接。
5. 切回「对话」不会自动开始新的语音对话，需要再唤醒 Nia。

## 行为与隐私边界

- 本机不创建录音文件，不使用 MediaRecorder，也不持久化音频片段；仅保存转写文字、时间及会话元数据。
- 这不是离线识别。音频仍通过现有 Codex Realtime / WebRTC 服务识别；服务端数据保留政策与账户费用仍由服务商决定，本功能不承诺云端零保留或降低云端费用。
- 转写模式通过 `server_vad.create_response=false` 禁用自动回答，并阻断文字消息、复习提醒、助手文字落盘和远端音频播放。遇到意外生成响应时发送取消请求。
- 服务端确认无回答配置之前，麦克风音轨不传送声音。配置不被确认、配置超时或连接失败时释放麦克风，而不是仅显示错误。
- 转写会自动保存文字，即使「保存新对话」关闭也会保存；原有对话保存偏好不会被改变。
- 结束时未收到最终确认的已有文字片段会标为「未确认片段」。尚未识别出来的声音无法从文字恢复，因为没有保存录音；不能保证断网或退出瞬间的最后几个字完整。
- 不做说话人分离或身份识别。这里记录的是麦克风收音内容，不能保证区分用户与其他在场者。
- 页面实时预览只保留最近 500 段，完整已识别文字保存在本机历史。关闭页面不会自动结束正在运行的伴侣转写；请明确点击「结束转写」。
- 启动应用不自动开始转写。停止后的转写也不会因定时提醒或点击桌面伴侣而重新开始。

## 实现与验证

复用既有 `NiaRealtimeTransport`、Electron companion coordinator 与 SQLite conversation store，不新增凭据入口、IPC 命令或数据库表。通过现有 wake 请求的 mode 字段选择模式。切换模式先完成旧会话关闭，防止转写文字混进语音对话。

参考本地 VMark 固定副本 `449fbc3e0` 的 `src/plugins/blockAudio/BlockAudioNodeView.ts` 后，确认其功能是媒体文件播放/加载，不适用于不落盘的实时 ASR，因此复用 Auris 已有实时语音链路，不复制媒体存储实现。

验证涵盖：协议配置、无回答确认、文字/提醒阻断、意外回答取消、增量与最终文本去重、尾句收集、模式切换、文字存储与保存偏好、显式同意与暂停/停止 UI，以及原有 Nia 回归。测试使用模拟语音服务，没有采集真实谈话或调用真实云端识别；识别准确率和当前账号服务兼容性仍需用户主动启动后验收。本次不替换已安装应用，也不提交或发布。
